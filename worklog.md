# Worklog

- Fixed revenue reporting to recognize only posted/sent/paid invoices and aggregate the materialized invoice total instead of mutable order/product data. Added focused tests for status filtering, invoice-level adjustments, deleted-live-data independence, and quarterly/customer/annual grouping.
- Replaced duplicated server/client response interfaces with a shared Zod contract package whose TypeScript models are inferred from runtime schemas. Server DTO mappers and report aggregators now validate their output, while Prisma remains the generated source for internal database record types.
- Added a pure bigint-backed pricing engine for product, hourly, subscription, tiered, discount, tax, and aggregate calculations, returning fixed two-decimal money strings. Unit tests cover float-error regressions, rounding/tier boundaries, floors/ceilings, invalid inputs, and exact aggregation; controller cutover will follow the database expansion.
- Replaced the hand-written rate-tier type guards with the shared Zod schema and inferred type, so persisted pricing JSON and API models use one executable definition. Added regression tests for valid/null storage and malformed, non-finite, or invalid-bound tiers.
- Added an exact legacy baseline plus an expand-only financial-integrity migration: nullable Decimal twins, order-time product/rate/pricing snapshots, invoice bill-to/line snapshots, constrained lifecycle transitions, and database-enforced posted invoice/order immutability. The migration preserves legacy columns, performs no table scan or destructive rebuild, and includes a tested baseline/deploy/batched-backfill runbook with explicit SQLite and PostgreSQL guidance.
- Added strict Zod request contracts and inferred types for every existing API route, covering path/query/body shape, ISO dates, positive quantities and payments, unique IDs, tier consistency, and transmission enums. Routers now validate before invoking business logic and return stable field-level `400 VALIDATION_ERROR` responses; focused contract tests exercise valid and invalid payloads.
- Hardened invoice transmission so only posted/sent invoices can be delivered, snapshotted recipients are revalidated with Zod, PDFs are rendered and attached before success is recorded, and missing portal/API configuration no longer falls back to `"unknown"`. Successful transmission plus invoice state now commit atomically, while rendering/provider/attachment failures create redacted `FAILED` records; behavioral tests verify ordering and negative paths.
